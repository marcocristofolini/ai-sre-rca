Docker 29.9.2, BuildKit, overlayfs, 6 logical CPUs, 19 GiB reported Linux RAM (Docker limit 20,973,735,936 bytes), 8 GiB swap. No Windows, WSL, Docker Desktop, power, or thermal settings were changed. Build operations were run serially where possible; no thermal telemetry was available. Raw logs and timings are in `/tmp/ai-sre-perf-*` and are not committed.

The `--no-cache` runs retain BuildKit download caches and were sequential, so they are **uncached image builds**, not reproducible first-download cold starts. Their timing differences include cache state and normal system variability; they are local observations, not production guarantees. The original frontend warm image was rebuilt from its original Dockerfile and primed before the timed run. The interim 29.36 s build changed Dockerfile inputs and is excluded. Process RSS from `/usr/bin/time` measures the Docker CLI, not container or daemon peak memory. At the initial snapshot, Linux reported 3.2 GiB used RAM and 180 KiB swap used; after validation, 2.5 GiB and 1.3 MiB. Neither is a peak measurement. Docker build cache grew from 19.25 GB to 22.89 GB while retaining all existing cache. PostgreSQL used about 66 MiB in one `docker stats` snapshot.

Changes: dependency installation now precedes backend source and test copies; pip and npm use BuildKit download caches; Docker contexts exclude generated content. Compose startup uses existing images, with an explicit `compose-build` target and backend readiness before frontend startup. `test-docker-run` reuses a built test image. Next-step Copilot questions now return the same deterministic answer without a model call; a test verifies one model request for a separate question and zero additional requests for next steps. Actual token savings need provider usage telemetry and were not measured.

Validation: backend PostgreSQL suite passed 296 tests before and after, including three alternating runs per image in the follow-up; validation harness unit suite passed 50 tests; 31 focused Copilot tests passed with a mocked provider, authorization, audit, citations, and deterministic next-step behavior. Production backend and frontend images built; standalone frontend served HTTP 200 and included static/public assets; Compose config and `git diff --check` passed. Independent diagnosis, Copilot v1, Copilot v2, dynamic scope, and live Kind Playwright runners passed. Showcase was not applicable because this branch has no `/showcase` route. The first full Kind attempt stopped before benchmark execution because the local demo API occupied workload port 18080; it cleaned up. The corrected run used port 18180 and completed in 544.53 s. Its six original real-telemetry scenarios passed, with no source errors, stale-evidence promotion, false confirmations, or failed evidence hashes. The live benchmark retained l001/l003 correct abstentions and l002 partial diagnosis on all three paths, matching the historical report; 9/9 scored paths passed integrity checks and the strict benchmark remains FAIL. Synthetic and frozen legacy classifications, query counts, and integrity counts matched the committed v2.1 report exactly. A temporary retained Copilot cluster passed 6/6 scenarios and enabled the live Playwright runner; it and all associated containers and port forwards were removed afterward.

Three paired unchanged-input backend builds gave original 2.65/0.78/0.81 s and optimized 2.19/1.26/1.23 s (p50 0.81 versus 1.26 s). The first original run included source-layer work, so only the later two original runs represent a fully warm cache; the warm difference is around 0.45 s and comes from the additional cached dependency/package layers. It is smaller than the verified benefit of keeping dependency installation independent of source and test edits, so the layer split remains. Three alternating PostgreSQL suite runs per image gave original 11.83/11.09/11.01 s and optimized 11.60/10.96/11.15 s (p50 11.09 versus 11.15 s); the initial one-run regression was noise. Uncached builds still have only one observation each and no valid p50. They retain download caches, as noted above.

During the corrected full Kind run, `vmstat` sampled 599 seconds: peak CPU busy was 79% of six logical CPUs, peak used WSL RAM excluding cache was 2.65 GiB, and peak swap occupancy was 889.8 MiB; swap-in totaled 35.4 MiB and swap-out 0.1 MiB. Sampled Docker container maxima were worker 316% CPU/1123 MiB, control plane 381%/816 MiB, PostgreSQL 58%/84 MiB, and harness 89%/241 MiB; these peaks were not simultaneous. No before resource trace exists, so no resource improvement is claimed. Fast development reused images and demo-only browser fixtures; full validation used a disposable Kind cluster; benchmark scoring used unique tenant identities, independent oracle data, fresh source checks, and isolated PostgreSQL jobs/audit. No xdist or extra BuildKit parallelism was added: fixtures share PostgreSQL and no isolated-worker or sustained-throughput measurement justified it. The real harness deliberately destroys its Kind cluster by default; persistent infrastructure reuse was rejected because old telemetry and incident identities could invalidate benchmark freshness and isolation. Codex usage telemetry was unavailable. Local LLM execution was disabled, so the report's zero model tokens are not a measured token saving.
